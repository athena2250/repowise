## 🧭 Learning roadmap

Use this as a suggested sequence. Adjust it as you discover the codebase and its current priorities.

### Phase 1 — Setup and orientation
- [ ] Read the project README and contribution guidelines.
- [ ] Read the project roadmap and understand the major goals.
- [ ] Fork/clone the repository and configure the development environment.
- [ ] Install dependencies and run the project locally.
- [ ] Run the existing test suite and record the baseline.
- [ ] Identify the main packages, entry points, and configuration files.

### Phase 2 — Understand the architecture
- [ ] Map the high-level architecture and major components.
- [ ] Trace one end-to-end workflow through the code.
- [ ] Understand how the MCP server and its tools are organised.
- [ ] Explore code health and complexity analysis.
- [ ] Explore documentation generation.
- [ ] Explore Git analytics and repository history features.
- [ ] Explore dead code detection and related analysis.
- [ ] Understand how architectural decisions are represented.
- [ ] Identify the key data models, interfaces, and service boundaries.

### Phase 3 — Find a contribution
- [ ] Review open issues and discussions.
- [ ] Identify a beginner-friendly issue or a small documentation improvement.
- [ ] Reproduce the issue or verify the proposed improvement.
- [ ] Write down the expected behaviour and acceptance criteria.
- [ ] Discuss the approach before making a large or breaking change.
- [ ] Create a focused branch for the change.

### Phase 4 — Implement and validate
- [ ] Make the smallest useful change.
- [ ] Add or update tests.
- [ ] Run relevant tests.
- [ ] Run formatting, linting, and type checks where applicable.
- [ ] Review the diff for unrelated changes, debugging code, and secrets.
- [ ] Update documentation if behaviour or usage changed.
- [ ] Commit with a clear message.

### Phase 5 — Contribute and reflect
- [ ] Open a pull request with context, implementation details, and test evidence.
- [ ] Respond to review feedback.
- [ ] Make requested revisions and rerun checks.
- [ ] Record what was learned.
- [ ] Note the next small, concrete task.

## ✅ A good daily session

A focused 30–90 minute session is enough. Use this simple loop:

1. **Orient:** Pick one question or small task.
2. **Explore:** Read the relevant code and trace how it works.
3. **Try:** Run a command, test a hypothesis, or make a small change.
4. **Verify:** Check the result and run relevant tests.
5. **Record:** Update this log before you stop.

Do not measure progress only by lines of code or commits. Understanding a module, reproducing a bug, writing a test, or improving documentation are all real progress.
